# Atlas 检索评测

衡量检索质量的两套互补口径。词法路径在固定语料与配置下结果确定；混合路径还
依赖外部嵌入服务。比较改动时应固定语料与向量，不能把两次服务响应的差异归因于代码。

## 为什么需要基准

改动排序、打分、切分策略前，必须先能量出当前水平。这不是理论洁癖：本轮
优化过程中曾尝试 tier 分档、分词、authority 权重、标题索引和 IDF 加权。
但基准本身也需要验证：2026-09-18 发现评分遗漏无关结果的位置，缓存还丢失了
IDF 权重。此前的效果归因不能视为普适结论，见下方修正记录。

## 两套口径

### 排序质量（`run-retrieval-eval.mjs`）

沿用 OCE 评测框架的评分方式，便于横向对照：

| 维度 | 分值 | 含义 |
|---|---:|---|
| Top-1 | 1 分 | 首位结果是否命中期望文件；硬判定 |
| nDCG@10 | 0~1 分 | 前 10 条整体的可用程度；位置敏感，给部分分 |

相关性等级取自 `expected_files` 顺序：首项 rel=2（真正回答问题），其余 rel=1
（支撑上下文）。Top-1 沿用命中任一期望文件即得分的口径，不等同于只命中首项。
每个返回位置都参与折扣，无关项与重复项计 0；每个期望项及返回路径最多计一次。
支持 glob 模式。两条评测链共用 [metrics.mjs](metrics.mjs)，手算边界由
[test/eval.test.mjs](../test/eval.test.mjs) 锁定。

例如只期望 `answer.md`，返回 `[noise.md, answer.md]` 时，nDCG 应为
`1 / log2(3) ≈ 0.63093`，不能先过滤 `noise.md` 再计成 1。

```bash
node eval/run-retrieval-eval.mjs --repo <项目根> [--refresh] [--json]
```

两个维度分开读更有信息量：Top-1 高而 nDCG 低，说明能找准但上下文补得不够；
反过来说明召回到了却没排上去。

### 判据完整性（`score.mjs`）

对每条用例检查四个独立条件，任一不满足即失败：

- `expect` 列出的文件全部出现在结果中
- `forbid` 列出的文件一个都不出现（负例，防止把过程材料当成真源）
- `expectRoutes` 列出的显式路由全部命中
- 渲染后的上下文字节数不超过预算（默认 4000）

`expectMiss: true` 用于标记「词法层已实测到不了」的条目，这类只作记录，
不作硬判据——措辞与文档用词断层时，无论排序怎么调都命不中，把它算作失败
只会掩盖真实改进。

```bash
node eval/score.mjs --project <项目根> --prompts <用例文件> [--max-bytes N] [--json]
```

## 基准集

`benchmarks/app-manager-retrieval-benchmark.jsonl` —— 100 题，10 个类别 × 10 题，
满分 200。覆盖 app-manager 项目的 `docs/` 与 `.trellis/spec/` 全部知识文档。

| 类别 | 题数 | 考察点 |
|---|---:|---|
| file_exact_match | 10 | 按名称定位文件 |
| configuration_lookup | 10 | 配置项与约定的取值 |
| component_location | 10 | 组件与契约的归属位置 |
| api_usage | 10 | 接口调用方式与限制 |
| semantic_feature | 10 | 设计意图与原因 |
| error_handling | 10 | 故障处置与回滚 |
| architecture_understanding | 10 | 整体结构与边界 |
| cross_language | 10 | 中英混排查询（中文提问、英文标识符） |
| symbol_location | 10 | 精确标识符定位 |
| call_chain | 10 | 流程与调用链还原 |

难度按 `difficulty` 字段分 1/2/3 三档标注。

`prompts.app-manager-bench.jsonl` 是同一批用例的 `score.mjs` 格式版本，
用于跑判据完整性口径。

## 当前水平与修正记录

2026-09-18，以 app-manager 的 96 个索引文档、100 题为对象。下表全部使用
修正后的评分函数；改前结果保存后重新计分，避免把口径变化误算成排序变化。

| 路径 | Top-1 改前 → 改后 | nDCG@10 改前 → 改后 | 总分改前 → 改后（满分 200） |
|---|---|---|---|
| 词法，实际 CLI | 38 → 36 | 0.4886 → 0.5094 | 86.86 → 86.94 |
| 混合，实际 CLI，两次独立服务响应 | 49 → 45 | 0.6397 → 0.6233 | 112.97 → 107.33 |
| 混合，同一批查询向量配对比较 | 49 → 46 | 0.6394 → 0.6270 | 112.94 → 108.70 |

配对比较复用相同文档向量，每题只请求一次查询向量，再同时交给改前、改后实现。
96 道非显式路由题的返回文件及顺序完全一致。其余 4 题命中排他路由；Q01、Q71、
Q80 的项目配置要求先读部署拓扑再读发布 Runbook，因此答案首位分数下降。Q05
只移除了排他链以外的候选。改后实际 CLI 中 4 题为 `explicit`，96 题为 `hybrid`。
独立调用与配对结果也说明，外部服务下的混合分数不能承诺完全确定。

这是读取契约与缓存一致性的修复，**不是准确率全面提升**。Atlas 返回读取顺序，
显式链的先决资料不应为了答案 Top-1 被绕过。若项目的路由触发条件过宽，应由项目
缩窄配置；只有增加明确的“无序候选”配置契约后，才重新考虑语义重排显式链。

修复与对应证据：

- `Map` 直接 JSON 序列化成 `{}`，热缓存实际丢掉 IDF。显式序列化权重，并用缓存
  文档修复旧版空表；[test/retrieval.test.mjs](../test/retrieval.test.mjs) 检查分数、
  顺序和章节完全一致，且旧缓存修复不扫描仓库。
- 混合查询保留显式顺序、章节和排他集合；hook 恢复活动分支不查询最新一句话。
  [test/hybrid.test.mjs](../test/hybrid.test.mjs) 用固定向量验证，包括服务失败、
  空缓存、实际注入节点与 focus 一致、异步等待期间的分支切换。
- 两条评测脚本原来都在计分前压掉无关结果，导致虚高 nDCG。旧记录的混合
  `0.7925`、词法 `0.5877` 及由此求出的总分已经失效，不能与本表直接比较。

聚合结果、语料指纹和变化题目见
[本轮评测记录](results/2026-09-18-routing-contracts.json)。

复测命令：


混合评测凭据配置见 [new-project.md](../plugins/atlas/rules/new-project.md#关于凭据)。

## 决策意图与同主题归并（2026-09-18，后续增量）

`context/route --intent current|history` 对已分类决策进行状态筛选，默认 `all` 保持
通用检索。新增 [12 题决策级验收集](benchmarks/decision-intent.json) 测实际选中的
决策 ID，而非只看文件：当前与旧索引格式、拒绝远程存储的理由、令牌有效期取代、

## 早期实验记录（归因待复核）

以下数字保留为历史证据，使用旧评分与缓存实现，不能证明独立改动的当前收益。
重访时应固定语料、缓存及向量，以修正后的指标和读取契约共同判断。

| 改动 | 效果 | 结论 |
|---|---|---|
| 修复代码块内 `#` 被误判为标题 | 无分数变化 | **真 bug，必留**：第 86 行的 shell 注释吞掉其后 674 行，标题层级失真 |
| tier 从排序主键改为加权系数 | +4.7 | 有效：低档文档原先无论多相关都无法晋升 |
| 任务工件移出候选 | +3.0 | 有效：prd.md 复读查询词，词面得分高出知识文档十倍 |
| 章节级索引 + 祖先标题链 | 0 | 词法下无效；对语义有 +2.5，保留 |
| IDF 加权 | 0 | 独立使用无效；与标识符加成组合后有效 |
| 结构化标识符加成 | +2.0 | 有效：`tabvisits` 类标识符文档频率极低，区分度高 |
| **嵌入语义检索** | **+12.0** | 有效：解决「按概念提问、知识用实体名存储」的断层 |
| 拆分 760 行的 quality-guidelines.md | 词法 -0.6 / 语义 +2.5 | 语义下有效；对词法无效（高频词文档仍然赢） |
| 融合权重扫描 | +4.7 | 词法权重设为 0 最优：它引入的噪声拖累语义排序 |

代码可以直接证实：`tokenize` 已有中文 2/3-gram 切分。标题、拆分、词汇桥接、
权重的效果则依赖语料与评测，不应写成“不要重试”的永久禁令。模型、语料、查询
分布或评分口径变化时，旧结论需要重新验证。

## 已知天花板

概览文档可能排在具体契约前；标题嵌入、有限候选数和显式读取链都会影响分数。
单一项目的 100 题不能证明通用上限，也不能由 nDCG 推断“答案几乎总在前十”。
答案召回、章节是否含答案、读取链是否完整是不同问题，当前基准没有全覆盖。

## 已知边界

词面匹配对同一概念的不同措辞无能为力。比如「首页聚合层为什么不直接联表」
要回答的内容写在名为 `数据源与 Redis 边界` 的章节里，两者没有一个共同词。
这类查询仅靠调整词面分数无法解决。可选嵌入已用于弥补措辞差异，但依赖外部
服务，不承担确定性保证；显式路由和离线词法路径仍独立可用。覆盖度阈值也只是在
特定语料和模型上的启发式提示，不证明候选含有答案，更不证明事实仍然有效。
